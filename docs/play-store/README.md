# 구글 플레이 내부 테스트 등록 안내

자비스 안드로이드 앱(`ai.jarvisglass.app`)을 플레이 콘솔 **내부 테스트** 트랙에 올리는 순서입니다. 콘솔 화면 이름과 요건은 2026년 11월 기준 기억에 의존해 쓴 부분이 있으니, 실제 콘솔에서 다시 확인해 주세요.

Meta 글라스 SDK는 개발자 미리보기 동안 테스터에게만 배포할 수 있습니다. 그래서 이번 목표는 프로덕션 공개가 아니라 내부 테스트(최대 100명)입니다.

## 2. 업로드 키 만들기(직접 실행)

비밀번호가 대화 기록에 남지 않도록 터미널에서 직접 실행합니다. 비밀번호는 묻는 창에 입력합니다.

```bash
mkdir -p ~/keys/jarvis
keytool -genkeypair -v -keystore ~/keys/jarvis/upload-keystore.jks \
  -alias upload -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=Jarvis, O=CrunchLabs, C=KR"
```

다음으로 `frontend/samples/CameraAccessAndroid/keystore.properties`를 만듭니다. `keystore.properties.example`을 복사해 채우면 되고, 이 파일은 git에 올라가지 않습니다.

```
storeFile=/Users/yskim/keys/jarvis/upload-keystore.jks
storePassword=입력한 비밀번호
keyAlias=upload
keyPassword=입력한 비밀번호
```

`.jks` 파일과 비밀번호는 반드시 따로 백업해 둡니다. 키를 잃어버리면 플레이 고객센터에 업로드 키 재설정을 요청해야 합니다.

서명된 번들 만들기:

```bash
cd frontend/samples/CameraAccessAndroid
./gradlew :app:bundleRelease -PversionCode=1 -PversionName=0.1.0
# 결과: app/build/outputs/bundle/release/app-release.aab
```

올릴 때마다 `versionCode`를 1씩 올립니다.

## 3. 플레이 설치본에서만 깨질 수 있는 것

플레이 앱 서명을 쓰면, 사용자 휴대폰에 설치되는 앱은 우리 업로드 키가 아니라 구글이 보관하는 **앱 서명 키**로 서명됩니다. 서명 지문에 묶인 기능은 플레이 설치본에서만 실패할 수 있습니다.

1. **구글 로그인**
   - 콘솔 > 테스트 및 출시 > 앱 무결성 > 앱 서명에서 **앱 서명 키 SHA-1**과 **업로드 키 SHA-1**을 복사합니다.
   - Google Cloud 콘솔 > 사용자 인증 정보에서 패키지 `ai.jarvisglass.app`용 **Android** OAuth 클라이언트를 지문마다 하나씩 만듭니다.
   - 웹 클라이언트 ID(`googleWebClientId`)는 지금 것을 그대로 씁니다.
   - 빠뜨리면 로컬 릴리스 빌드는 로그인되는데 플레이에서 받은 앱만 로그인에 실패합니다.
2. **Meta 개발자 센터**: 글라스 앱 등록이 패키지 이름이나 서명 지문을 요구하는지 확인합니다. 요구하면 앱 서명 키 지문도 함께 등록합니다.
3. **운영 서버**: 로그인, 사용자 분리, Gemini 중계 코드(1ad6f76~6d449bd)는 아직 로컬에만 있습니다. 운영 서버에 올라가 있지 않으면 플레이 빌드는 로그인부터 실패합니다.

### 4-4. 데이터 보안 양식

내부 테스트만 열어 둔 동안에는 이 양식을 내지 않아도 됩니다. 비공개 테스트나 프로덕션으로 넘어갈 때 아래 답안을 씁니다.

모든 전송은 암호화(https/wss)됩니다. 사용자가 계정을 지우면 서버 데이터도 지워집니다. 데이터를 판매하거나 광고에 쓰지 않습니다.

| 데이터 유형(콘솔 분류) | 수집 | 공유 | 목적 | 필수 여부 |
|---|---|---|---|---|
| 개인 정보 > 이름, 이메일 주소 | 예 | 아니요 | 계정 관리 | 필수 |
| 개인 정보 > 사용자 ID | 예 | 아니요 | 계정 관리 | 필수 |
| 오디오 > 음성 또는 소리 녹음 | 예 | 예(AI 처리 업체) | 앱 기능 | 필수 |
| 사진 및 동영상 > 사진 | 예 | 예(AI 처리 업체) | 앱 기능 | 선택 |
| 연락처 | 예(사용자가 고른 연락처, 명함에서 읽은 정보) | 아니요 | 앱 기능 | 선택 |
| 캘린더 일정 | 예(미팅 브리핑과 먼저 알려 주기에 쓰는 일정, 백그라운드에서 읽음) | 예(AI 처리 업체) | 앱 기능 | 선택 |
| 메시지 > 이메일 | 예(지메일을 연결한 사용자가 메일 내용을 물을 때만 읽음, 서버에 저장 안 함) | 예(AI 처리 업체) | 앱 기능 | 선택 |
| 앱 활동 > 기타 사용자 제작 콘텐츠(미팅 기록, 메모) | 예 | 예(AI 처리 업체) | 앱 기능 | 필수 |
| **개인 정보 > 기타(얼굴 인식 정보)** | 예(D37에서 끄기로 하면 제외) | 아니요 | 앱 기능(만난 사람 알아보기) | 선택 |

- "공유"는 음성과 사진을 AI 모델(Google Gemini, 중계 업체 Mindlogic)에 보내 처리하는 것을 뜻합니다. 서비스 제공자가 우리를 대신해 처리하는 경우라 콘솔 기준으로는 "공유 아님"으로 볼 수도 있습니다. Google과 Mindlogic이 우리 지시대로만 처리하고 받은 데이터를 학습에 쓰지 않는다는 약관이 확인되면 "공유 아님"으로 바꿀 수 있습니다(D35).
- 얼굴 인식 정보는 사진에서 뽑은 숫자 벡터(512차원)만 저장하지만, 생체 정보이므로 반드시 신고합니다.

### 4-5. 포그라운드 서비스 신고

`StreamingService`는 안경판에서 두 유형(connectedDevice, microphone)을, 휴대폰판에서 microphone 하나만 씁니다. 유형마다 사유와 시연 영상(유튜브 미등록 링크 등)을 요구합니다.

| 유형 | 사유(콘솔 입력 문구) |
|---|---|
| connectedDevice | 사용자가 연결한 스마트 안경과 블루투스 연결을 유지하고 안경 카메라 영상을 받습니다. (안경판만) |
| microphone | 사용자가 "자비스"라고 불러 대화를 시작하면 화면이 꺼져 있어도 음성 대화를 이어 갑니다. |

dataSync는 쓰지 않습니다. 안드로이드 15부터 백그라운드에서 하루 6시간이 지나면 시스템이 서비스를 끝내 앱이 멈출 수 있어서 상시 듣기와 스트리밍에서 뺐습니다(D36). 사진과 미팅 기록 업로드는 대화 화면이 열려 있는 동안 처리하고, 끊기면 다음에 다시 보냅니다.

### 4-5-1. 지메일 연결(구글 클라우드 콘솔)

지메일은 안드로이드 권한이 아니라 구글 계정 연결(OAuth)로 받습니다. 서버의 기존 구글 캘린더 연결에 메일 읽기 권한(`gmail.readonly`)을 더하는 방식이라 새 클라이언트는 필요 없습니다.

1. 구글 클라우드 콘솔 > API 및 서비스 > 라이브러리에서 **Gmail API**를 사용 설정합니다(서버 `.env`의 `GOOGLE_CLIENT_ID`가 속한 프로젝트).
2. OAuth 동의 화면(Google 인증 플랫폼) > 데이터 액세스에 `https://www.googleapis.com/auth/gmail.readonly` 범위를 추가합니다. 캘린더 범위 `calendar.events`도 있는지 확인합니다.
3. 게시 상태가 「테스트」인 동안에는 대상 > 테스트 사용자에 테스터 구글 계정을 넣어야 연결됩니다(최대 100명).
4. 앱 설정 > 서비스 연결 > 지메일 > 연결을 누르면 구글 화면에서 캘린더와 메일 읽기 권한을 함께 묻습니다. 메일 읽기 항목을 체크해야 연결됨으로 바뀝니다.

`gmail.readonly`는 구글이 「제한된 범위」로 분류합니다. 서버로 메일을 가져와 처리하므로, 테스트 사용자 밖으로 공개하려면 구글 앱 확인과 구글이 지정한 외부 기관의 보안 평가(CASA, 12개월마다 다시)를 통과해야 합니다. 그 전까지는 테스터 전용 기능입니다.

게시 상태가 「테스트」인 동안 구글은 연결 토큰을 7일만 유지합니다. 7일이 지나면 지메일과 구글 캘린더 모두 다시 연결해야 합니다(앱은 「연결 필요」로 안내함).

### 4-6. 민감 권한
- 전화 걸기(CALL_PHONE), 연락처, 캘린더, 마이크, 카메라, 블루투스: 별도 신고서 대상은 아닙니다. 데이터 보안 양식과 개인정보처리방침에 사용 목적만 맞게 적으면 됩니다.
- 문자(SMS)와 통화 기록 권한은 쓰지 않습니다.

## 5. 웹에 올릴 페이지

플레이는 개인정보처리방침 URL과 **앱을 설치하지 않고도 계정 삭제를 요청할 수 있는 웹 URL**을 요구합니다. 초안은 같은 폴더에 있습니다.

- `privacy-policy.md`: 개인정보처리방침
- `delete-account.md`: 계정 삭제 안내

게시 위치 후보는 회사 사이트 `crunchlabs.projectjarvis.biz/jarvis/privacy`, `/jarvis/delete-account`입니다. 게시는 공개 작업이라 확인을 받은 뒤 진행합니다(D34).

## 6. 내부 테스트 올리기

1. 테스트 및 출시 > 테스트 > 내부 테스트 > 새 버전 만들기
2. 플레이 앱 서명 사용에 동의(기본값)
3. 서명된 `app-release.aab` 업로드, 출시 노트 입력
4. 테스터 탭에서 이메일 목록 만들기(구글 계정 이메일)
5. 검토 후 출시 → 테스터에게 참여 링크 전달
6. 3절의 앱 서명 키 SHA-1을 Google Cloud에 등록

참고로 2023년 11월 이후 만든 개인 개발자 계정은 프로덕션에 올리기 전에 비공개 테스트를 일정 인원·기간 이상 운영해야 합니다(당시 기준 12명, 14일). 내부 테스트에는 이 조건이 없습니다.
