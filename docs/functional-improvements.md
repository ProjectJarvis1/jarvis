# 기능 개선 1~6 구현 기록

> 이후 안정화·UI·DB 개편이 추가됐다. 최신 동작과 검증 제한은 [2026-10-17 개편 기록](architecture-and-ux-2026-10-17.md)을 참고한다. 아래 테스트 결과는 최초 구현 당시 기록이다.

대상은 Android 주 클라이언트와 공용 FastAPI 백엔드입니다. iOS 포팅은 이번 변경에 포함하지 않습니다.

## 1. 대화 대상 연결

`resolve_reference` 도구가 보관된 완료 작업에서 사진·기억·사람·회의 후보를 찾습니다.
대상 종류, 내용 검색, 사용자가 명시한 순번으로 좁히며 후보가 여러 개면
`needs_clarification`을 반환합니다. 취소·실패 결과는 참조에서 제외합니다.
서버 기록을 수정하거나 삭제하면 이전 캐시 참조는 제거하고 새 조회가 필요합니다.

순번은 현재 보관된 해당 종류의 첫 등장 순서입니다. 캐시 만료 이후까지 영구적인 사진 번호를
제공하는 기능은 아닙니다. 음성 지시어의 의미 해석은 모델이 수행하며 실제 모델 품질 평가는 별도입니다.

## 2. 작업 목록과 이어하기

카메라 화면의 **작업 · 기록** 버튼으로 작업 목록을 엽니다. AI 대화가 종료되어도
같은 화면에서 결과를 확인할 수 있습니다.

- 진행·확인 대기·통신 복구 대기·실패·보류·결과 불확실 상태 표시
- 사진 및 분석 결과 확인
- 작업 취소, 아직 외부로 전달하지 않은 실패·보류 작업 재시도
- 저장·수정·일정 생성의 내용을 확인한 뒤 실행 승인

외부로 이미 전달한 작업 취소는 자동 되돌리기가 아닙니다. 전송된 작업의 취소는
결과 불확실 상태가 될 수 있으며, 원래 버전의 자동 재전송을 중단합니다.

## 3. 저장 전 수정과 기록 정정

저장 도구와 일정 생성은 `WAITING_USER` 초안을 먼저 만들고 화면 승인을 기다립니다.
사용자가 메모·이름·제목·설명 등을 수정하면 버전을 올리고, 이전 버전의 승인은 거부합니다.
현재 이 승인 경로는 화면 버튼 기준이며 음성만으로 승인하는 기능은 추가하지 않았습니다.
전화·문자는 기존 전용 확인 흐름을 사용합니다.

저장된 기록은 다음 절차로 수정합니다.

1. 작업 결과의 근거 카드에서 **기록 수정**을 선택합니다.
2. 서버의 최신 원문 전체를 불러옵니다. 잘린 검색 발췌를 원문으로 덮어쓰지 않습니다.
3. 변경 미리보기를 만든 뒤 변경 전후를 확인합니다.
4. 적용 요청 작업을 열어 승인합니다.
5. 적용된 수정은 **수정 되돌리기 요청**으로 다시 확인 후 되돌립니다.

지원 필드:

- 기억: 검색용 본문 `text`
- 사람: 이름, 조직, 직책, 전화번호, 이메일, 메모
- 회의: 제목, 요약, 장소

현재 화면의 빠른 편집은 기억 본문·사람 이름·회의 요약을 제공합니다. 다른 지원 필드는
음성 `prepare_record_change` 도구로 미리보기를 만들 수 있습니다.

서버는 PostgreSQL 행 버전을 비교하여 미리보기 이후 다른 수정이 생겼다면 적용을 거부합니다.
수정 후 타인이 다시 편집한 경우 오래된 되돌리기도 거부합니다. 기억 수정은 임베딩을
다시 생성하고 이전 추출 라벨·엔티티 연결을 정리합니다. 되돌릴 때 원래 메타데이터와 연결을 복구합니다.

**저장 취소 · 삭제 미리보기**는 기억 DB 기록을 삭제합니다. 삭제 자체를 복구하는 휴지통은
이번 범위가 아닙니다. 서버 이미지 파일의 물리적 정리는 별도의 보관 정책이 필요합니다.
사람·회의 삭제는 이 새로운 미리보기 API에서 허용하지 않습니다.

## 4. 통신 복구와 중복 방지

서버 변경 요청마다 `task_id:revision`을 `Idempotency-Key`로 전달합니다.
앱은 정확한 요청 본문을 앱 전용 `outbox/`에 원자적으로 저장합니다.
API 키는 이 파일에 저장하지 않으며 서버 주소와 키의 해시로 다른 계정·서버로의 재전송을 막습니다.

- 네트워크 장애·408·429·서버 오류 시 `WAITING_NETWORK`로 보관
- ViewModel이 살아 있는 동안 15초 주기로 복구 시도
- 프로세스 재시작 후에도 작업과 전송 대기 파일을 읽어 같은 키·본문으로 복구
- 취소되어 버전이 달라진 요청은 재전송하지 않음
- 서버가 원자적 요청 처리를 지원하는지 확인한 후에만 저장 요청 전송

서버는 같은 키를 사용하는 요청들을 DB 트랜잭션 잠금으로 직렬화합니다.
기존 핸들러의 DB 변경과 응답 영수증을 같은 트랜잭션에서 커밋하므로
응답 유실 후 재전송해도 DB 변경이 중복되지 않습니다.
같은 키로 다른 본문을 보내면 409를 반환합니다. 실패 응답은 DB 변경을 롤백합니다.

적용 범위는 `/people`, `/meetings`, `/memory/save`, `/memory/life/save`, `/needs`,
그리고 새 수정 미리보기·적용·되돌리기 API의 키가 있는 JSON POST입니다.
외부 전화·문자·캘린더, 회의 오디오 업로드, 모델 호출 비용, 파일 생성까지
정확히 한 번 실행되는 것은 아닙니다. 다른 키로 새 요청을 만들면 별도 작업입니다.

OS가 앱을 종료한 동안에는 전송하지 않습니다. WorkManager 기반 상시 백그라운드 전송은
포함하지 않습니다. 서버의 `request_receipts`는 재시도 안전성을 위해 자동 삭제하지 않습니다.

## 5. 근거가 보이는 검색

완료된 검색 결과를 작업 상세의 근거 카드로 표시합니다.

- 원본 기록 제목·발생 시각·내용 발췌·기록 ID
- 저장된 사진을 API 인증 헤더로 조회
- 촬영 작업은 앱에 보관한 해당 버전의 실제 사진 표시
- 회의 기록에서 후속 업무 조회로 이동

카드는 조회 당시 기록임을 표시합니다. 수정할 때는 최신 원본을 다시 조회합니다.
모델 프롬프트에도 검색 답변의 근거를 제시하고 추측과 구분하도록 추가했습니다.
사진을 포함한 모든 검색 품질 및 음성 근거 설명은 실기기·실제 모델 검증이 추가로 필요합니다.

## 6. 회의 후속 업무

회의 전사 요약의 구조화 결과에 `followups`를 추가했습니다.
각 항목은 `task`, `owner`, `due_at`, `evidence`를 가집니다.

원문에 없는 근거는 제외하고, 담당자·기한이 해당 근거에 없으면 빈 값으로 둡니다.
예전 회의는 기존 `action_items`를 담당자·기한 미정 항목으로 표시합니다.
새 추출을 기존 회의에 자동 재실행하거나 외부 AI를 자동 호출하지 않습니다.

회의 검색 결과 → **회의 후속 업무 보기** → 시작 일시 입력 → **일정 등록 확인 요청** →
작업 상세에서 승인 → 기기의 캘린더 작성 화면에서 최종 저장 순서입니다.
앱은 캘린더 화면을 열었음을 알리며, 실제 저장 완료로 단정하지 않습니다.
날짜가 불명확하면 사용자가 시간대 포함 일시를 지정해야 합니다.

## 배포 및 검증

백엔드를 먼저 업데이트하고 재시작하세요. `ensure_schema()`에서
`request_receipts`와 `assistant_changes`를 생성합니다. 이후 새 Android APK를 사용합니다.
이전 서버에는 복구 가능한 저장 요청을 보내지 않도록 기능 지원 여부를 확인합니다.

검증 명령:

```bash
# 저장소 루트, Android
frontend/samples/CameraAccessAndroid/gradlew -p frontend/samples/CameraAccessAndroid \
  :app:testDebugUnitTest :app:assembleDebug

# 별도 테스트용 pgvector DB 필요. 운영 DB로 실행하지 마세요.
TEST_DATABASE_URL='postgresql://USER:PASSWORD@localhost:PORT/TEST_DB' \
  python -m pytest backend/jarvis-server/tests/test_assistant_transactions.py -q
```

백엔드 테스트는 테스트용 DB에 스키마와 데이터를 생성합니다. 임베딩은 테스트 대역을 쓰고,
트랜잭션·잠금·중복 응답·수정·되돌리기는 실제 PostgreSQL로 검증합니다.
실제 음성·기기·외부 AI 호출은 이 테스트에 포함하지 않습니다.

### 확인한 결과

- Android: JVM 테스트 34개 통과, debug APK 빌드 성공.
- 백엔드: 별도 pgvector 테스트 DB에서 통합 테스트 9개 통과.
- Python 전체 구문, 문서 링크, Git 공백 검사 통과.
- 테스트용 DB는 검증 후 종료했으며 운영 DB에는 접속하지 않음.
- 실제 기기·음성 모델·캘린더 앱·iOS 검증은 미수행.

전송 대기 파일은 64MB 상한을 적용하며 완료한 요청과 취소로 버전이 변경된 요청을 정리합니다.
서버 주소나 API 키가 바뀌면 다른 계정으로 보류 요청을 보내지 않으므로 원래 설정에서 복구하거나
서버 결과를 확인해야 합니다.
